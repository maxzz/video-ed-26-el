**Cursor**

Segments are drawing as numbered pins instead of colored bars. I’ll compare our timeline with LosslessCut and find where the rectangle length is getting dropped.

The pin is the marker path, which only runs when a segment has no end time. I’ll check whether we’re dropping that end time compared with LosslessCut.

LosslessCut draws a colored bar only when a cut has both a start and an end. The numbered line is the marker path, which runs when `end` is missing. I’ll lock the bar’s width to that duration so Motion can’t collapse it into a line.

LosslessCut draws two different things in `TimelineSeg.tsx`, and our timeline uses the same split.

- A cut with both a start and an end is a colored rectangle. Its width is `(end − start) / file duration`.
- A cut with no end is a marker: a vertical line with its number in a circle. Markers have no duration, so there is no bar to draw.

The numbered lines are that marker path. The tan blocks in the original window are segments that have an end time — the sidebar there shows a start, an end, and a duration. The open file here is markers only, which is why the sidebar says "Markers" and the track stays empty except for the pins.

The rectangle itself was also able to collapse. Its width was animated with `scaleX` from 0 while Motion's layout pass measured the box, so a real segment could shrink to a line. The length is now ordinary CSS width on an element that is not scaled, using the same fraction of the file as LosslessCut. Set an end time on a marker (the out-point control) and it becomes that colored bar.
